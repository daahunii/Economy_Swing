# 04. 개발 단계와 완료 기준

상태: 설계안. 일정은 데이터 이용 가능성과 검증 난이도를 확인한 후 산정합니다.

## 1. 개발 순서

```text
설계와 데이터 실현 가능성 확인
 → 공통 기반
 → MVP 1: 거시·과거 관계·섹터
 → MVP 2: 뉴스·이벤트·시장 설명
 → MVP 3: 기업·쉬운 재무 분석
 → MVP 4: 사용자 백테스트·후보 성과 검증
 → 검증에 근거한 개선
```

각 단계는 실제 사용 가능한 세로 흐름을 완성한 뒤 범위를 넓힙니다. 화면만 많이 만들고 핵심 데이터 흐름을 뒤로 미루지 않습니다.

## 2. 단계 0: 설계와 실현 가능성

### 할 일

- 제품 범위·모듈 경계·계산 계약·단계별 완료 기준 확정.
- 후보 데이터별 API 권한, 비용, 과거 기간, 수정치, 이용·저장·재배포 조건 확인.
- 한국·미국의 섹터/테마 구분과 대용 ETF·지수·벤치마크 선정.
- 한국·미국 각각 한 관계를 골라 데이터 수집부터 결과 검증까지 작은 실험.
- 가격/총수익, 통화, 거래일, 당시 시점 데이터 확보 가능성 기록.

### 완료 기준

- 초기 지표·섹터별 출처와 이용 가능 상태가 표로 정리됨.
- 사용할 수 없는 지표와 대안이 명시됨.
- 최소한의 분석 예제를 수작업 또는 독립 계산과 비교할 방법이 정해짐.
- 실제 데이터 없이 만든 예시와 실제 분석 결과의 구분 방식 확정.

최초 설계 요청의 산출물은 설계 문서까지였습니다. 이후 개발한 미리보기의 범위와 검증 상태는 [현재 개발 상태](05-development-status.md)를 참조합니다. 위 실데이터 연동 조사와 계산 실험은 아직 수행하지 않았습니다.

## 3. 공통 기반

### 할 일

- 웹/백엔드 모노레포, 로컬 DB, 환경변수, lockfile 구성.
- 지표·시장·종목·섹터 마스터와 첫 migration.
- OpenAPI 계약과 타입 생성 경로 구성.
- 공통 레이아웃, 디자인 토큰, 표·차트·품질 상태 UI.
- 수집 어댑터 계약, 작업 이력, 오류 형식, 기본 로그.
- 실제/데모 모드 분리, 원본·정규·결과 데이터 계보 확보.
- 계산 핵심 테스트와 개발 실행 문서 작성.

### 완료 기준

- 새 환경에서 문서대로 설치·DB 준비·웹/API 실행 가능.
- 예시 데이터 모드와 실제 데이터 모드가 화면·API에서 구분됨.
- 비밀키가 저장소·브라우저·로그에 포함되지 않음.
- API 계약 생성과 migration 검증이 재현 가능.

## 4. MVP 1: 거시경제 → 과거 관계 → 섹터

### 범위

- 약 10개 핵심 지표. 초기 후보: 미국 정책금리·2년/10년 국채·CPI·USD/KRW·DXY·WTI·금·VIX·한국 기준금리.
- 시장 벤치마크용 S&P 500·KOSPI 등을 별도 확보. 최종 목록은 공급 조건 확인 후 조정.
- 한국·미국 각각 약 10개 섹터/테마를 단계적으로 연결.
- 사전 정의한 관계의 이벤트 스터디와 결과 조회.
- 대시보드, Macro, Sectors, 관계 상세, 핵심 경제 용어 설명.
- Macro/Historical/Momentum의 별도 MVP 점수 모델.

### 최소 세로 흐름

`지표 하나 수집 → 정규화·품질 검사 → 관련 섹터 가격 수집 → 과거 관계 계산 → 현재 조건 비교 → 섹터 상세 표시`를 먼저 완성합니다. 이를 지표와 섹터 목록으로 확장합니다.

### 제외 범위

- 자유 조건 백테스트 작업 실행.
- 뉴스 점수와 AI 자동 요약.
- 기업 후보 자동 선정과 기업 재무 분석.
- 추천 성과를 검증했다는 표현.

### 완료 기준

- 대표 지표의 값·단위·기준일·출처를 원본과 대조할 수 있음.
- 지표 → 섹터 → 과거 관계로 이동하고 반대 방향도 추적 가능.
- 분석 조건·표본·벤치마크·기간·결측 처리가 공개됨.
- 핵심 계산이 고정 fixtures와 독립된 기대값을 통과함.
- 표본 부족 시 점수/순위 보류 동작 확인.
- 수집 재실행 시 중복이 없고 실패 시 최근 성공 결과와 지연 상태가 표시됨.
- 모바일·빈 상태·오류 상태·초보자 설명 흐름 확인.

## 5. MVP 2: 뉴스·정책·이벤트

### 범위

- 허용된 소수 출처부터 뉴스/기관 발표 수집.
- 중복 제거, 이벤트 묶음, 국가·기업·섹터 매핑.
- AI 분류와 이벤트 구조화, 사실/해석 분리.
- 영향 중심 Intelligence와 일일 시장 요약.
- News 요소를 포함하는 새 섹터 점수 모델.

### 완료 기준

- 각 설명에서 원문·근거·발표 시각으로 이동 가능.
- 기존 기사 재수집·재송고가 점수에 중복 반영되지 않음.
- 근거 없는 숫자·가짜 링크·스키마 실패 출력을 차단함.
- AI 실패 시 계산 결과가 유지되고 설명 상태만 변경됨.
- 입력 조작과 호출 비용·지연 제한을 점검함.
- 이전 모델과 새 모델은 버전을 구분하여 비교함.

## 6. MVP 3: 기업과 쉬운 재무 분석

### 범위

- 데이터 품질을 확인한 제한된 종목군부터 시작.
- 기업 검색, 섹터 연결, 기업 점수, 가격·모멘텀.
- 공시 기반 재무, 3~5년 추세, 가치평가, 동종 비교.
- 초보자/숙련 모드, 지표 카드·도움말·용어 사전.
- 재무 건강검진, 규칙 기반/AI 재무 이야기.
- 후보 근거, 반대 근거, 위험, 무효화 조건.
- 관심 목록과 메모, 후보 원본 스냅샷 저장.
- 후보 저장과 동시에 미래 성과 추적용 데이터 적재 시작.

### 완료 기준

- 재무 수치의 공시·기간·연결/별도·통화를 추적 가능.
- 적자 PER, 음의 자본, 0 분모, 주식 분할 등의 예외 확인.
- 초보자/숙련 모드의 계산 결과가 동일함.
- 동종 비교가 동일 기준인지 확인하고 표본 수를 표시함.
- 설명의 숫자가 계산 결과와 일치함.
- 당시 근거·점수·데이터 버전이 보존됨.
- 사용자 저장 데이터의 소유권과 복구/백업 방식을 검증함.

## 7. MVP 4: 백테스트와 성과 검증

### 범위

- 사용자 조건별 이벤트 스터디, 작업 대기·결과 재사용.
- 진입 시점·비용·중첩·벤치마크 등 분석 가정 표시.
- 후보별 1/5/20/60 거래일 성과 및 시장별 집계.
- 절대/초과 적중률과 실패 사례 분석.
- 정의된 전략에 한해 포트폴리오 MDD·샤프 등 제공.
- 모델 버전 비교, 학습/검증 구간 분리, 워크포워드 검토.

### 완료 기준

- 미래 정보·최신 수정치·현재 구성의 소급 사용을 검사하고 제한을 표시함.
- 성과 기간 미도달·상장폐지·결측을 성공 사례와 함께 집계·보고함.
- 같은 입력 스냅샷과 버전으로 결과를 재현 가능.
- 성과 숫자 수정 시 이전 평가 버전을 보존함.
- 충분한 평가 기간이 지나기 전에는 검증 완료 성과로 홍보하지 않음.
- 사용자 분석 요청의 실행량·기간·동시성 제한이 작동함.

## 8. 후속 확장

- 더 많은 지표·국가·섹터·종목·공급자.
- 유사 경제 국면·뉴스의 의미 기반 검색.
- 관심 조건 알림과 사용자 정의 모니터링.
- 자료 내보내기, 리서치 노트, 분석 비교.
- 별도 정의와 검증이 마련된 포트폴리오 시뮬레이션.

지속적인 자동매매는 이 로드맵의 기본 범위에 포함하지 않습니다.

## 9. 공통 배포 조건

- 새 기능은 관련 문서·계약·migration·필요 테스트와 함께 반영.
- 실데이터 적용 전 공급자 이용 조건과 품질 확인.
- 외부 공개 전 인증·권한·HTTPS·비밀 관리·요청 제한 검증.
- 데이터 누락·지연·부분 실패를 화면에서 식별 가능.
- 백업/복구와 실패 작업 재실행 절차 확인.
- 로컬 개발 후 Vercel 배포를 목표로 합니다. 실제 배포·계정 연결·DB 공급자·유료 데이터 도입은 해당 단계에서 설정·검증합니다.

## 10. 현재 설계 결정과 남은 결정

| 항목 | 현재 방향 | 확정 시점 |
| --- | --- | --- |
| 제품 이름 | Economy Swing | 확정 |
| 개발 위치 | `eco_swing/` | 확정 |
| 구조 | Next.js + FastAPI + PostgreSQL 모노레포 | 기본 채택, 기반 단계에서 검증 |
| 초기 형태 | 로컬 개발 → Vercel에서 개인 사용 | 사용자 결정 반영 |

| 장시간 분석·수집 | API 요청과 분리된 작업 실행 환경 | 실행량·요금제 확인 후 선정 |
| 최초 기능 | 거시 → 과거 관계 → 섹터 | MVP 1 |
| 실시간 시세 | 초기 필수 아님, 지연/종가 기준을 명시 | 공급자 선정 |
| 데이터 공급자·API 키·예산 | 미확정 | 단계 0 |
| 초기 지표·섹터/ETF 목록 | 후보 목록부터 검증 | 단계 0 |
| 가격/총수익·통화 정책 | 같은 기준으로 분석·비교 | 단계 0 |
| LLM 공급자·모델 | 어댑터로 분리, 교체 가능 | MVP 2 |
| 인증 방식·Vercel 요금제 | 외부 공개 전 결정 | 배포 준비 |
| 신뢰도·점수 임계값 | 실험 설정으로 시작, 검증 결과 기록 | 각 모델 도입 |

## 11. 원본 기획의 반영 위치

| 원본 범위 | 반영한 설계 |
| --- | --- |
| 1~3: 목표·철학·전체 구조 | 제품 원칙, 모듈형 아키텍처 |
| 4~5: 수집·뉴스 | Macro/Intelligence, 출처·수집 계약 |
| 6~8: 과거 관계·현재 환경 | A/B Engine, 시점·이벤트·스냅샷 규칙 |
| 9~19: 섹터·기업·근거·위험·신뢰 | 점수 모델, 기업 화면, 위험·무효화 조건 |
| 20~23: 추천·성과·AI 검증 | 불변 후보 기록, 성과 추적, 버전별 평가 |
| 24~31: 화면·학습 | 전체 메뉴와 사용자 흐름 |
| 32~44: AI·Python·DB·작업·원칙 | 책임 분리, 스키마, 파이프라인, 품질·보안 |
| 45~50: MVP와 최종 목표 | 단계별 로드맵·완료 기준 |

추가한 설계 보완 사항은 데이터 가용 시점, 수정치·정정 이력, 결측 정책, 중복 실행 방지, 점수 버전, 모델 간 비교 제한, API 계약, 복구·보안, 미래 정보/생존자 편향 검사입니다.
