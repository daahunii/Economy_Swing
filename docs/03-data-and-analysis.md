# 03. 데이터와 분석 규칙

상태: 설계안. 실제 공급 계약, 데이터 품질, 검증 결과에 따라 조정합니다.

## 1. 출처 정책

기본 우선순위는 정부·중앙은행·거래소·기업 공시 → 공식 API → 신뢰할 수 있는 금융 데이터 제공자 → 언론 → 커뮤니티/SNS입니다. API라는 형식만으로 내용의 권위를 높게 평가하지 않습니다.

| 영역 | 검토할 출처 | 구현 전 확인 항목 |
| --- | --- | --- |
| 미국 거시 | FRED, Federal Reserve, BLS, BEA | 시계열 ID·단위·주기·수정치·발표 시각·이용 조건 |
| 한국 거시 | 한국은행 ECOS, KOSIS, 산업통상자원부 | 통계 코드·단위·발표 주기·수정·권한 |
| 시장·ETF | 거래소 또는 이용이 허용된 공급자 | 수정주가, 배당, 상장폐지, 지연, 재배포, 과거 구성 |
| 기업·공시 | 한국·미국 공식 공시 및 허용된 공급자 | 연결/별도, 회계 기준, 공시 가용 시점, 정정 이력 |
| 뉴스·정책 | 공식 API, 기관 발표, RSS, 공개 웹 | 저장·요약·재배포 조건, 원문 링크, 정정·중복 |

위 목록은 연동 후보이며 현재 연결됨을 뜻하지 않습니다. 크롤링은 이용 조건과 기술적 허용 범위를 확인한 경우에만 검토합니다.

## 2. 시간과 식별자

### 2.1 반드시 구분할 시간

- `observation_date` / `period_end`: 실제 관측일 또는 회계 기간 말일.
- `published_at`: 공식 발표 시각. 정확한 시각을 모르면 정밀도를 별도로 기록.
- `available_at`: 제품/해당 공급 경로에서 알 수 있게 된 시각.
- `ingested_at`: 이 시스템이 실제 수집한 시각.
- `vintage_at`: 통계 수정·공시 정정 버전의 기준 시각.
- `as_of`: 특정 분석이 사용 가능한 정보를 제한하는 기준 시각.
- `computed_at`: 결과를 계산한 시각.

타임스탬프는 UTC로 저장하고 시장/사용자 시간대로 표시합니다. 날짜만 제공되는 값은 임의 시각으로 확정하지 않습니다. 데이터별 시간대와 거래소 캘린더를 관리합니다.

### 2.2 마스터와 시계열

- 기업, 상장 종목, 거래소, 섹터, 지표는 내부 ID로 연결.
- 티커·기업명·섹터 편입·대용 ETF·벤치마크 연결에는 유효 시작/종료일 부여.
- 통화, 단위, 빈도, 계절조정, 가격 조정 방식은 메타데이터로 관리.
- 현재 구성 종목만 과거에 소급 적용하지 않음.

## 3. 논리 데이터 모델

아래는 논리적 엔터티입니다. 실제 물리 테이블은 단계별로 생성하며, 조회 요구에 맞게 나눕니다.

| 그룹 | 엔터티 예시 | 핵심 내용 |
| --- | --- | --- |
| 출처 | `data_sources`, `source_policies` | 출처·조건·신뢰도·라이선스·허용 보관 기간 |
| 마스터 | `indicators`, `markets`, `exchanges`, `sectors` | 지표 정의·주기·단위·시장 분류 |
| 종목 | `companies`, `instruments`, `instrument_identifiers` | 기업과 상장 증권 분리, 티커 이력 |

| 거시 | `macro_observations` | 관측치·발표·가용·수정 버전 |

| 과거 관계 | `relationships`, `relationship_observations` | 정의별 집계 및 개별 이벤트 결과 |

| 사용자 | `users`, `watchlist_items`, `user_preferences` | 사용자 소유 저장·초보자 모드·시간대 |

문자열 JSON에 모든 것을 넣지 않습니다. 검색·필터·관계·유니크 제약이 필요한 필드는 정형 컬럼으로 두고, 공급자별 부가 정보와 고정 스냅샷에 JSONB를 사용합니다.

### 3.1 핵심 제약과 인덱스

- 거시 관측치: 지표·관측일·출처·수정 버전의 중복 방지.
- 가격: 종목·타임프레임·시각·공급자·조정 버전 기준 중복 방지.
- 공시: 공식 식별자·정정 버전, 계정·기간·연결/별도 범위 구분.
- 분석 결과: 정의·입력 스냅샷·모델 버전·평가 기간 기준 식별.
- 성과: 후보 기록·평가 기간·평가 버전 기준 식별.
- 시계열에는 대상 ID+시각 복합 인덱스. 실제 쿼리를 보고 추가 인덱스 결정.
- 후보 원본의 외래키와 계보는 삭제로 깨지지 않도록 보관 정책 적용.

## 4. 데이터 품질

| 상태 | 의미 | 제품 동작 |
| --- | --- | --- |
| `fresh` | 해당 지표의 예정 주기 내 정상 자료 | 정상 제공 |
| `stale` | 예정 갱신이 지났지만 마지막 정상 자료 있음 | 시각·지연 표시, 모델 정책에 따라 계산 제외 |
| `missing` | 필수 자료 없음 | 값/점수 없음, 이유 제공 |
| `invalid` | 단위·범위·형식 검사 실패 | 계산 차단, 격리 |
| `partial` | 일부 선택 자료만 확보 | 확보 범위와 제한 표시 |
| `demo` | 예시·합성 fixture | 실제 데이터와 분리, 성과 집계 제외 |

- 월간 지표가 며칠 전 값이라는 이유만으로 오래된 데이터로 판단하지 않음.
- 휴장일의 시세 부재와 공급 장애를 구분.
- 결측을 0으로 바꾸거나 과거 빈 구간에 미래 값을 채우지 않음.
- forward-fill은 지표별 허용 정책과 만료 시점이 있는 경우에만 사용하며 원본을 보존.
- 급격한 변화는 자동 삭제하지 않고 이상치 검토 상태로 표시.
- 원본 정정으로 재계산한 결과와 당시 공개한 결과를 별도 보존.

## 5. A Engine: 과거 경제 관계

### 5.1 분석 정의에 포함할 조건

- 변수, 국가, 방향, 변화 구간, 임계값, 이벤트 발생 규칙.
- 공식 발표 이벤트인지 일별 임계값 돌파 이벤트인지 구분.
- 이벤트 발생 시각과 실제 진입 가능 시점.
- 섹터 대용 지표, 통화, 벤치마크, 가격/총수익 기준.
- 분석 시작/종료일, 보유 거래일, 이벤트 중첩 처리.
- 거래 비용·슬리피지·환전 가정의 적용 여부.
- 최소 표본, 결측·상장폐지·거래정지 처리, 데이터 버전.

예: `미국 10년 금리의 5거래일 변화 ≤ -20bp`와 `연준 금리 인하 발표`는 서로 다른 이벤트입니다. 임계값은 연구 설정으로 저장하며 검증 없이 최적값으로 취급하지 않습니다.

### 5.2 기본 계산

```text
기간 수익률 = (종료 조정가격 / 진입 조정가격 - 1) × 100
초과 수익률 = 대상 수익률 - 동일 기간 벤치마크 수익률
절대 승률 = 수익률 > 0인 유효 이벤트 수 / 유효 이벤트 수
초과 승률 = 초과 수익률 > 0인 유효 이벤트 수 / 유효 이벤트 수
평균 = 유효 이벤트별 결과의 산술평균
최대 낙폭 = 관측 경로의 누적 고점 대비 하락률 중 가장 낮은 값
```

- 수익률 차이는 `%p`, 금리 변화는 `bp` 또는 `%p`로 표시.
- T+1/5/20/60/120은 해당 시장 거래일 기준. 진입 시점은 전략 정의로 고정.
- 최대 낙폭 계산에는 구간 내 가격 경로가 필요. 시작·끝 값만으로 만들지 않음.
- 평균·중앙값·분위수·표본 수·분석 기간을 함께 제공.
- 이벤트별 낙폭 요약과 포트폴리오 전체 낙폭을 다른 지표로 명명.
- 개별 이벤트 평균 초과 수익률을 운용 포트폴리오 수익률로 표시하지 않음.
- 상관계수에는 정렬된 표본·시차·변화율/수준값 여부를 명시.
- 신뢰구간이 도입되면 방법과 독립성 가정을 공개. 중첩 사건에는 적절한 재표집 방법 검토.

샤프 비율은 무위험수익률, 수익률 빈도, 연율화, 포트폴리오 구성 및 재조정 규칙이 정의된 전략 시뮬레이션에서 산출합니다.

### 5.3 왜곡 방지

- 발표 시각 이후 사용 가능했던 데이터만 사용. 장 마감 후 발표는 그 전에 진입했다고 계산하지 않음.
- 최초 발표값/당시 수정치가 없는 경우 결과를 `최신 수정치 기반 탐색`으로 표시하고 당시 시점 백테스트와 구분.
- 상장폐지 종목과 과거 구성 변경을 고려. 자료가 없으면 생존자 편향 제한 표시.
- 같은 거시 사건에 겹쳐 발생한 여러 신호의 의존성과 표본 중복을 표시.
- 임계값·가중치를 조정한 학습 구간과 별도의 검증 구간 분리.
- 다수 변수·섹터 탐색에 따른 우연한 발견 가능성 기록. 좋은 결과만 골라 공개하지 않음.
- 반복 검증용 고정 기간과 워크포워드 평가를 구분.

## 6. B Engine: 현재 환경 분석

1. 기준 시각별 사용 가능한 거시·가격·이벤트 스냅샷 구성.
2. 지표별 수준·변화·가속도·조건 충족 여부 계산.
3. 해당 시점 이전 자료로 검증한 관계만 선택.
4. 현재와 과거 조건의 일치·불일치 및 반대 변수 확인.
5. 섹터별 요소 점수 → 종합 점수 → 적격 여부 계산.
6. 기업 단계 도입 시 섹터 내 기업을 비교.
7. 계산 결과로 설명을 생성하고 검증한 뒤 공개.

시장 상태 분류는 버전 관리된 규칙으로 시작합니다. Risk-On / Neutral / Risk-Off와 성장·물가 국면은 다른 축으로 관리합니다. 데이터가 모자라면 `판정 보류`이며 AI가 상태를 임의로 보충하지 않습니다.

## 7. 점수 모델

### 7.1 섹터 최종 목표 모델의 초기 가중치

| 요소 | 가중치 | 내용 |
| --- | --- | --- |
| Macro | 25% | 현재 경제 환경과 산업 영향 |
| Historical | 25% | 과거 관계의 방향·일관성·표본 |
| News | 20% | 검증된 이벤트의 관련성·신선도·반대 근거 |
| Momentum | 20% | 시장 대비 추세·가격·거래량 |
| Valuation | 10% | 동일 산업/자체 과거 대비 가격 수준 |

### 7.2 기업 최종 목표 모델의 초기 가중치

| 요소 | 가중치 | 내용 |
| --- | --- | --- |
| Sector | 25% | 해당 섹터 환경 |
| Fundamental | 20% | 성장·수익성·현금흐름·안정성 |
| Momentum | 20% | 상대 강도·추세·거래량 |
| Valuation | 15% | 동종 및 과거 대비 가격 |
| News | 10% | 공시·실적·기업 이벤트 |
| Risk quality | 10% | 위험이 낮을수록 높은 점수 |

`Risk quality`와 별도로 위험도 `낮음/보통/높음`을 표시하여 위험이 높으면 기회 점수가 올라가는 부호 혼동을 방지합니다.

### 7.3 MVP 모델과 결측 처리

- 위 가중치는 검증 전 가설이며 확정된 우수 모델이 아님.
- MVP 1은 `Macro + Historical + Momentum`만 사용하는 별도 `sector-mvp-v1` 모델로 시작.
- MVP 1의 가중치는 초기 후보로 35% / 40% / 25%를 두되, 실데이터 점검·검증 전에는 실험 설정으로 명시.
- News·Valuation이 아직 없는 것을 0점으로 넣거나 최종 모델 점수인 것처럼 표현하지 않음.
- 각 모델은 포함 요소·가중치·정규화·필수 입력·유효성 조건을 선언.
- 필수 입력 결측이면 종합 점수 산출 보류. 선택 입력 제외·재분배는 모델 정의에 명시된 경우만 허용.
- 서로 다른 모델 점수는 같은 순위표에서 직접 비교하지 않음.

### 7.4 공통 산출 규칙

```text
요소 점수: 0~100, 유리할수록 높음
종합 점수: Σ(요소 점수 × 모델 가중치)
저장: 원본 입력 + 정규화 결과 + 요소별 기여 + 모델 버전
```

정규화는 같은 국가·업종·기준일 비교 집단과 역사적 분포 중 무엇을 사용했는지 명시합니다. 극단값·작은 표본·결측·경계값 정책도 버전 관리합니다. UI에는 소수점 정밀도를 과도하게 노출하지 않습니다.

## 8. 신뢰도는 별도 축

- Opportunity Score: 해당 모델에서의 상대적 기회 우선순위.
- Data Confidence: 출처, 커버리지, 신선도, 표본, 조건 일치도 등 근거 충실도.
- LLM Extraction Confidence: 텍스트 구조화의 확신 정도. 정량 분석의 통계 신뢰도와 다름.

High / Medium / Low 판정은 설정된 규칙과 이유를 함께 보존합니다. 최소 표본만 충족했다고 High로 승격하지 않습니다. AI 공급자의 자체 confidence 값을 그대로 통계적 신뢰도로 사용하지 않습니다.

## 9. 재무 지표와 동종 비교

- TTM / 연간 / 분기, 연결 / 별도, 기본 / 희석 EPS를 명시.
- 과거 재무는 공시가 사용 가능해진 시점 이후부터 분석에 반영.
- 통화 변환, 배수, 회계 기준, 회계연도 차이를 맞춰 비교하거나 차이를 표시.
- 재무비율의 분자·분모·기간·버전을 함께 저장.
- PER 음수/정의 불가, PBR의 음의 자본, 0 분모는 오류 또는 해석 불가로 처리하고 낮은 값으로 정렬하지 않음.
- FCF는 적용한 정의와 투자 항목을 명시. 업종별 해석 제한 포함.
- 업종 비교 집단·표본 수·평균/중앙값·이상치 처리 공개.
- Forward PER 등 전망치는 당시 전망 기준일과 공급자·범위를 보존.
- 재무 건강검진은 업종별 규칙 기반. AI가 임의로 판정을 바꾸지 않음.

## 10. 뉴스와 AI 설명

### 10.1 입력 계약

AI에는 허용된 뉴스 텍스트, 검증된 이벤트, 계산 완료된 수치, 근거 ID, 데이터 제한 사항, 설명 템플릿만 전달합니다.

### 10.2 출력 계약

```text
summary
observed_facts[]          # 확인한 사실과 근거 ID
interpretations[]        # 가능한 해석과 연결 논리
opportunity_reasons[]
counter_evidence[]
risks[]
thesis_break_conditions[]
limitations[]
evidence_ids[]
```

- 사실과 해석을 분리. 본문 숫자가 원본 근거와 일치하는지 검사.
- 임의 수익률·승률·가격 목표·출처 생성 금지.
- 인용 근거가 없거나 입력에 없는 숫자가 나오면 해당 설명을 공개하지 않음.
- AI 실패 시 계산 결과와 규칙 기반 설명 유지, 설명 실패 상태 표시.
- 모델·프롬프트·입력 해시·생성 시각·검증 상태를 보존.
- 동일 스냅샷 설명은 재사용하여 비용과 불필요한 문구 변화를 제한.
- LLM은 호출·처리 시간·건당 비용 상한을 적용하고 무제한 재시도하지 않음.
- 뉴스 원문 지시는 데이터로만 처리하며 시스템 실행 권한을 부여하지 않음.

## 11. 후보와 성과의 재현성

후보 편입 시 `as_of`, 데이터 스냅샷, 분석 실행, 모델 버전, 점수 분해, 근거, 위험, 무효화 조건, 기준 가격 정책, 벤치마크를 고정합니다.

- 성과 진입 가격은 후보 공개 후 실제 관측 가능한 가격으로 정하며 규칙을 표시.
- 수익률은 같은 통화·보유 기간·배당/조정 기준으로 비교.
- 거래비용 미포함 결과는 명시. 비용 포함 결과와 혼합 집계 금지.
- 아직 평가일이 오지 않았으면 `pending`으로 유지. 미도달을 0% 또는 실패로 계산하지 않음.
- 상장폐지·거래정지·결측을 제외할 때 제외 수와 이유를 보고. 유리한 사례만 남기지 않음.
- 정정 재계산은 새 평가 버전으로 보존하며 당시 공개 성과를 소급 덮어쓰지 않음.
- 후보들의 단순 평균과 가중치·재조정·진입·청산 규칙이 있는 포트폴리오 성과를 구분.

```json

    "reasons": ["실제 데이터 미연동"]

```

필수 데이터가 없을 때 값을 꾸미지 않고 `null`과 이유를 반환하는 것이 기본입니다. 실제 구현 시 Pydantic/OpenAPI로 계약을 확정합니다.
